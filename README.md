# MediHiStat-Lite

Приложение Windows (.NET 8, WPF) для просмотра данных пациентов и статистических сравнений. Данные находятся в `mydatabase.db` рядом с запускаемым приложением. Статистический анализ читает существующие значения; исходные измерения и схема SQLite при расчётах не изменяются.

## Как выбрать данные

1. Задайте фильтры в таблице характеристик и нажмите **«Отобразить группу»**.
2. Для межгруппового сравнения сохраните первую выборку выбором показателя в поле **«Группа 1»**, затем сформируйте вторую выборку и выберите показатель в **«Группа 2»**. Состав сохранённых групп показан в окне анализа. Межгрупповые критерии требуют разных пациентов в группах.
3. Нажмите **«Выбрать режим анализа…»**, выберите задачу, показатель и сроки. При анализе одной группы второй набор пациентов не требуется. Если первая группа ещё не сохранена, используется текущая отображённая выборка.
4. Выберите поправку и проверьте состав семейства сравнений. Нажмите **«Рассчитать»**. В окне результатов доступны копирование и CSV.

## Режимы анализа

| Задача | Расчёт |
|---|---|
| Сравнить уровни показателя между двумя группами | Двусторонний Манн–Уитни отдельно в выбранные сроки |
| Сравнить изменения показателя между группами | Для каждого пациента вычисляется `Δ = позднее − раннее`; Манн–Уитни сравнивает индивидуальные Δ |
| Сравнить два срока внутри одной группы | Двусторонний критерий Уилкоксона для полных пар |
| Проверить нормальность уровней или изменений | Шапиро–Уилка или Колмогорова–Смирнова с калибровкой Лиллиефорса |
| Сравнить категории | χ² Пирсона или двусторонний Фишер для разреженной таблицы 2 × 2 |

Положительная Δ означает увеличение значения; отрицательная — уменьшение. Клинический смысл направления зависит от показателя. Уилкоксон оценивает изменение внутри группы, а сравнение Δ — различие изменений двух групп. Сравнение Δ не выполняет регрессионную корректировку ANCOVA и не оценивает всю траекторию восстановления.

## Пропуски и категории

- Пары собираются по идентификатору пациента и названию показателя. Для каждой пары нужны оба конечных числовых значения. Пустая запись, отсутствующая строка и нечисловое значение учитываются как недоступное измерение; измеренный ноль сохраняется.
- Повторный идентификатор в выбранной группе и дубли выбранного пациента/показателя блокируют расчёт. Программа не выбирает произвольную строку из дублей.
- Для характеристик пациентов доступны пол, основной диагноз и операция. Диагноз и операция анализируются как целое записанное значение; список сопутствующих болезней автоматически не преобразуется в признаки «есть/нет».
- Проценты категорий имеют знаменатель **число пациентов с известной категорией**. Общее число выбранных пациентов и пропуски выводятся отдельно. Частоты доступны и тогда, когда во всех записях только одна категория, но тест связи в таком случае не рассчитывается.
- Пробелы и регистр в названиях категорий нормализуются. Синонимы и разные медицинские формулировки автоматически не объединяются.
- При трёх и более категориях с малыми ожидаемыми частотами χ² сопровождается предупреждением; точный метод для такой таблицы не реализован.

## Настройки методов

**Уилкоксон.** Нулевые разности исключаются перед ранжированием по правилу Wilcox, но остаются в числе полных пар. Совпадающие абсолютные разности получают средние ранги. До 100 ненулевых пар вычисляется точное условное распределение перестановок знаков, включая связанные ранги; далее используется нормальное приближение с поправкой дисперсии и поправкой на непрерывность 0,5. Если все разности нулевые, выводятся `p = 1` и эффект 0 по явно указанному соглашению. Предпосылка теста — независимые пациенты и симметрия распределения разностей при нулевой гипотезе.

**Нормальность.** Шапиро–Уилка требует минимум три значения; Лиллиефорс — четыре. При нулевой дисперсии тест не рассчитывается. Шапиро–Уилка не переключается автоматически на другой метод при 50 пациентах; для выборок больше 5000 выводится предупреждение о точности p. Лиллиефорс использует таблицу критических значений statsmodels, основанную на 10 000 000 моделирований; значения за пределами калибровки показываются как границы p. Для поправок используется консервативная верхняя оценка. `p > 0,05` не доказывает нормальность.

**Множественные сравнения.** Доступны Холм, Бонферрони и расчёт без поправки. Семейство состоит из выбранных проверок **одного показателя в одном режиме**; другие показатели автоматически не включаются. Для характеристики пациента семейство содержит одну выбранную характеристику. Если отдельную выбранную проверку выполнить нельзя, её место сохраняется при коррекции, а вместо результата показывается причина. Семейства проверок нормальности и лечебных различий рассчитываются отдельно.

## Проверка и сборка

```bash
dotnet run --project StatisticsVerification/StatisticsVerification.csproj --configuration Release
dotnet build MediHiStat.sln --configuration Release
dotnet publish MediHiStat.csproj --configuration Release --runtime win-x64 --self-contained true --output publish
```

Контрольные наборы включают независимые результаты SciPy и statsmodels, полный перебор знаков для связанных рангов, проверку пропусков, дублей, измеренных нулей и недоступных вычислений. GitHub Actions запускает проверки и создаёт Windows-сборку для веток `main`, `update1`, `update2`, `update3` и Pull Request в `main`.

Атрибуция адаптированных статистических алгоритмов и таблиц: [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).
